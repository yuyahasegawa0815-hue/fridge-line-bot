# Fridgy（フリッジー）

Fridgy は、LINEで使う冷蔵庫の在庫管理ボットです。家族のLINEグループに招待しても、友だち追加して1対1のトークで一人で使ってもかまいません。冷蔵庫（在庫・買い物リスト・食費）はグループごと、個人トークは人ごとに分かれます。設計方針は「冷蔵庫管理ツール MVP設計方針」ドキュメントを参照してください。

## いまできること（段階1〜4）

- グループにレシートの写真を送る → AI（Claude）が品名・金額を読み取り、確認画面のリンクを返す
- 確認画面（LIFF）で品名・金額・保存場所を直し、食材でない行を外して「在庫に登録」
- 冷蔵庫の中の写真を送る → AI が写っている食材と残量の目安を挙げ、選択画面のリンクを返す。今ある物にチェックし、買った日（おおよそ）を選んで登録。写らなかった物は手で足せる。すでに在庫にある物は最初はチェックを外す
- レシートでも冷蔵庫でもない写真には反応しない
- 期限は食材マスタの目安日数から自動で入る（マスタにない食材はAIの目安でマスタに追加）
- トークで「在庫」→ 一覧、「追加 いちご 398」→ 手入力で追加。「追加」のあとに1行1件で書けばまとめて登録でき、残量（半分など）・冷蔵/冷凍/常温・「3日前」も書ける（すでに冷蔵庫にある物やレシートを忘れた物向け）
- 一覧画面の「食材を追加」から、買った日・残量・保存場所を選んで登録
- 一覧画面で残量（たっぷり／半分／少し）、使い切った、捨てたを記録し、期限を手で直す
- 夕方17時ごろ：期限が今日の食材だけをグループに通知（1日1回。LINEの無料通数を節約するため）
- 通知の各食材に「減った」（1段階ずつ減らす）「使い切った」「捨てた」ボタン。捨てたときは残量分の金額をロス費として記録
- 対象がない回は通知しない（LINE の無料通数の節約）
- トークで「献立」→ 在庫から期限が近い物を優先して3品提案（「献立 和食で」のように希望も書ける）。各料理の「買い足す物をリストへ」で足りない材料を買い物リストに追加
- トークで「買い物」→ 買い物リスト、「買う 牛乳 卵」→ リストに追加
- 買い物リスト画面（LIFF）でチェック・削除・追加。最近使い切った／捨てた物を買い足し候補として表示
- レシートを登録すると、同じ名前の買い物リストの項目は買ったことになる
- 「使い方」（「ヘルプ」「？」でも）で、登録・記録・献立・食費の使い方をまとめて案内
- トークで「食費」→ 今月の食費・廃棄額と先月との差。食費は買った月の食材の金額、廃棄額は捨てた月に「金額 × 捨てたときの残量」で数える
- 食費画面（LIFF）で月ごとの食費・廃棄額、種類別の内訳、捨てた物、半年の推移
- 毎月1日の夕方に、先月の食費と廃棄額をグループに送る（記録がない世帯には送らない）
- 日本語・英語・フランス語・韓国語・中国語（簡体字）に対応。言語はグループ／個人トークごとに1つで、最初に話しかけた人（個人トークは友だち追加した人）の LINE アプリの言語に自動で合わせる。「言語」（language など）で選び直せる。トークの返事・通知・使い方、AI が読み取る品名やレシピ、LINE から開く画面が切り替わる。コマンドはどの言語の言葉でも通じる（例：在庫／fridge／frigo／재고／库存）
- 日本語以外の品名（milk、우유 など）は、AI で日本語の食材マスタに結びつけて期限の目安を出し、マスタの別名として覚える

## 構成

| 役割 | 使うもの |
| --- | --- |
| ボット | LINE Messaging API（`app/api/line/webhook`） |
| 確認・一覧画面 | LIFF（`app/receipts/[id]`、`app/inventory`、`app/shopping`、`app/report`） |
| 夕方の通知 | Vercel Cron（`vercel.json`）→ `app/api/cron/notify` |
| サーバー | Next.js（Vercel にデプロイ） |
| DB・画像保存 | Supabase（`supabase/migrations`、`supabase/seed`） |
| レシート読み取り | Claude API（`src/lib/receipt-ai.ts`） |

## セットアップ

1. **Supabase**：プロジェクトを作り、SQL エディタで `supabase/migrations/0001_init.sql` → `supabase/seed/food_master.sql` → `supabase/migrations/0002_fridge_photo.sql` → `supabase/migrations/0003_language.sql` の順に実行。Storage に非公開バケット `receipts` を作る。
2. **LINE**：LINE Developers でプロバイダーを作り、次の2つのチャネルを作る。
   - Messaging API チャネル：チャネルシークレットとチャネルアクセストークン（長期）を控える。「グループトーク・複数人トークへの参加を許可する」をオン、応答メッセージはオフ。個人トークの挨拶は Fridgy が送るので、LINE Official Account Manager の「あいさつメッセージ」もオフ。
   - LINE ログインチャネル：LIFF アプリを追加（サイズ Full、エンドポイント URL は Vercel の URL、スコープ `openid`）。チャネルIDと LIFF ID を控える。
3. **Claude API**：Claude Console で API キーを作る。
4. **Vercel**：このリポジトリをインポートし、`.env.example` の値を環境変数に入れてデプロイ。`CRON_SECRET` には長いランダム文字列を入れる（Vercel が定期実行のときにこの値を付けて呼び出す）。無料プランでは定期実行の時刻が指定した1時間の中で前後します。
5. Messaging API チャネルの Webhook URL に `https://<VercelのURL>/api/line/webhook` を設定して「検証」。
6. ボット（表示名「Fridgy」）を友だち追加し、夫婦のグループに招待する（一人で使うなら、友だち追加すると「1人で使う／共有する」を選ぶボタンが届く）。

## 開発

```sh
npm install
cp .env.example .env.local   # 値を入れる
npm run dev
npm test         # 期限計算のテスト
npm run typecheck
```

レシート読み取りは `claude-opus-5-5` を使い、方針判定で断られた場合はサーバー側で別モデルに切り替える設定（`fallbacks: "default"`）を入れています。
